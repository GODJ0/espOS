# espOS и espOS Studio — план дальнейшей разработки

Срез проекта: объединение изменений из архива от 13 октября 2026 года с актуальным Studio.

**Текущий этап — восстановить прямую доступность платы в домашней LAN и проверить подписанное сопряжение Wi-Fi v2.** Пользователь прошёл базовый USB/headless запуск на S3; автоматический вход в ROM остаётся нестабильным и требует доработки. Сроки не фиксируем до аппаратных результатов.

## 1. Что уже разработано

| Направление | Что есть | Статус |
|---|---|---|
| espOS | MicroPython-пакет, HAL, оконный менеджер, лаунчер, приложения hello/touch/sysmon/settings/about | Код есть; аппаратная проверка впереди |
| Дисплей и тач | Драйверы ILI9341 и XPT2046, конфигурация GPIO, калибровка методом наименьших квадратов с экстраполяцией и определением зеркальности, схема подключения | Не проверено на реальном комплекте |
| USB Studio | Прошивка, установка пакета, файлы, редактор, REPL; новый raw-REPL handshake на каждую операцию, обнаружение перезагрузки, запись через `.espos-tmp` + SHA-256 + rename без удаления оригинала | Программные проверки пройдены; запись на реальной flash не проверена |
| Прошивальщик | ESP32, S2, S3, C2, C3, C6; проверка семейства и заголовка, ROM-определение, адреса записи | Это поддержка прошивальщика, не перенос espOS на шесть семейств |
| Восстановление | Safe mode «RST, затем BOOT» в окне 1,5 с, диагностика, журнал, ручной выбор порта; без автоматической повторной записи | Программные проверки пройдены; тайминг на плате не проверен |
| Wi-Fi v2 | Статус, список, чтение/обновление существующих app-файлов, подтверждаемый reboot, подписанные challenge/ответы и ошибки, защита от replay | WLAN подключение и получение IP подтверждены выводом платы; подписанный обмен с ПК пока не прошёл |
| Управление доступом | USB-настройка, ротация токена, отзыв LAN, запрет неподписанного v1 | Аппаратная ротация/отзыв ещё не проверены |
| Простой старт | Выбор режима, пошаговая USB-установка S3 без экрана, профиль без дисплея/тача/LAN, проверка свежей загрузки, тест 2 + 2 | Базовый проход подтверждён пользовательскими фото/журналами; полная матрица аппаратных тестов не завершена |

Последний проверенный набор (espOS 0.1.1-mvp): 49 Bun-тестов, 33 Python-теста, браузерные mocks простого старта/USB-восстановления/Wi-Fi, TypeScript, lint и сборка. Это результаты программной проверки, а не доказательство работы радио, flash, дисплея или USB на физической плате. Исходные записи результатов: `espos-studio/task.md`.

Изменения пользователя объединены с актуальным Studio, включая последнюю OG-картинку. Исправлены SPI-транзакции дисплея и восстановление частоты после ошибок touch; добавлены тесты фактического драйвера. Boolean guard остаётся диагностикой повторного входа, а не thread/IRQ-lock. Подробности: `espOS/docs/SPI_MERGE.md`. Приоритеты этапов A–E не меняются.

Последние аппаратные результаты и блокеры: `espOS/docs/HARDWARE_STATUS.md`. Проверка через Ethernet сейчас недоступна; альтернативы — другой ПК в той же LAN, проверка изоляции роутера или отдельно согласованная тестовая сеть. Перепрошивка для диагностики сетевой доступности не требуется.

## 2. Этап A — реальная S3 и «Простой старт»

**Цель:** человек с платой и кабелем получает подтверждённый запуск без ручной настройки GPIO.

Что нужно от владельца платы:
- Полная маркировка модуля или чёткое фото; тип и объём flash/PSRAM по паспорту.
- ОС, версия браузера, используемый USB-разъём: USB–UART или native USB.
- Проход мастера от подготовки до первого USB-теста; при сбое — точный шаг и журнал без секретов.

Проверки:
1. Подключение и ROM-определение S3 без изменения flash.
2. Выбор подходящей stable-сборки; неизвестная память блокирует запись.
3. Подтверждённая установка MicroPython и отдельная проверка его ответа.
4. Подтверждённая установка espOS без внешних модулей.
5. Soft reset, свежий маркер готовности espOS, тест 2 + 2.
6. Отключение/переподключение USB: старые доказательства снимаются, запись не повторяется сама.
7. Safe mode: нажать и отпустить RST, затем сразу зажать BOOT на время `hold BOOT now`; лаунчер и LAN не запускаются, USB остаётся. BOOT, зажатый во время RST, — это ROM-загрузчик, не safe mode.
8. Запись файла через USB поверх существующего: оригинал заменяется только после проверки SHA-256; при ошибке rename остаётся `.espos-tmp`.

**Критерий готовности:** на документированном варианте S3 воспроизводимо проходит весь сценарий; USB-потеря не приводит к ложному успеху или скрытой повторной прошивке. Обнаруженные проблемы исправлены и покрыты регрессиями.

Не отключать питание специально во время записи на единственной рабочей плате. Разрушительные тесты — только отдельно, с резервной копией и согласованным способом восстановления.

## 3. Этап B — существующий Wi-Fi v2 на реальной плате

**Цель:** подтвердить сетевой обмен, не расширяя доступ и не теряя USB-восстановление.

1. Настройка защищённой изолированной LAN по USB, получение IP.
2. Подписанное сопряжение, status/list/read и запись резервной копии тестового app-файла.
3. Конфликт revision, явный reboot, повторная проверка сопряжения.
4. Потеря сети/timeout: результат write может быть неизвестен, автоматического повтора нет.
5. Ротация по USB: старый токен отвергается, новый проходит.
6. Отзыв по USB и reset: LAN становится недоступен, USB сохраняется.
7. Android-браузер → локальный Studio на ПК → плата; затем проверка iPhone как отдельной комбинации устройства/браузера.

**Критерий готовности:** подтверждённые операции и восстановление на реальной S3, запрет старого токена, отсутствие повторов после сбоя. HTTP не шифрует данные: для телефона → Studio по возможности локальный HTTPS; никаких публичных портов 4200/8765.

## 4. Этап C — удобство для новичка после базовых проверок

Предлагаемый следующий программный объём, до реализации согласуем:
- Профили конкретных проверенных модулей/комплектов вместо выбора абстрактного типа памяти. Неизвестную плату не угадывать.
- Понятное резервное копирование app-файлов перед заменой; предупреждать, что полный backup чужой прошивки отдельно.
- Мастер Wi-Fi: SSID/пароль, создание токена, USB-применение, ручная проверка сопряжения и отзыв; без автоматического включения сети.
- Простые USB-примеры без неизвестных GPIO и понятные сообщения «что произошло / что делать».
- Проверка сценария с начинающим пользователем и исправление шагов, где требуется помощь.

**Критерий готовности:** новичок проходит проверенный сценарий без ручного редактирования конфигурации и без отключения защитных подтверждений.

## 5. Этап D — дисплей и тач как отдельный комплект

- Сверить питание, контроллеры и логические уровни конкретного модуля. Не питать силовую подсветку от GPIO.
- Проверить распиновку, ориентацию ILI9341, XPT2046 и калибровку (приложение touch: первая точка не берётся из касания запуска, результат применяется на сессию; перенос в config.py — вручную).
- Проверить работу лаунчера и приложений, дисплей/тач одновременно с Wi-Fi, ошибки и safe mode.
- После аппаратного успеха добавить мастер проверенного комплекта, не обещая распознавания произвольной проводки.

**Критерий готовности:** опубликован точный профиль проверенного комплекта, запуск воспроизводим, USB-восстановление доступно при ошибке периферии.

## 6. Этап E — BLE

Начинать после стабильного USB и Wi-Fi. Сначала согласовать протокол и целевые устройства.

Порядок: безопасное сопряжение и статус → чтение файлов → ограниченная chunked-запись с подтверждением → явный reboot. Предусмотреть лимиты, таймауты, отключение посередине и восстановление. Произвольный удалённый Python exec не включать в первый BLE-этап.

**Критерий готовности:** реальные тесты на выбранных Android-устройствах, авторизация и восстановление после разрыва, отсутствие неавторизованных изменений. Поддержку iPhone не обещать через один только Web Bluetooth; подходящий клиент выбирается отдельно.

## 7. Поздние этапы — пока не обещание реализации

- Перенос самого espOS на другие семейства: отдельные HAL, pin/capability-профили и реальные платы. Начинать с одного согласованного семейства.
- Мобильный клиент, доступ без ПК и более защищённый транспорт: отдельная архитектура и security-review.
- MicroPython OTA: только после стратегии rollback и восстановления; обновление app-файлов сейчас не является OTA прошивки.
- Каталог приложений, манифесты, подписи, обновления и ограничения доверия к коду.
- Публичный релиз, хостинг, распространение и реклама — после аппаратных проверок и аудита; рекламные кампании не запущены.

## 8. Постоянные правила разработки

- Каждая новая функция имеет простой пользовательский сценарий и расширенный инструмент при необходимости.
- Автоматически выбираем только доказуемые параметры; неизвестные значения блокируют опасное действие.
- Не стирать, не перезаписывать и не включать сеть без явного согласия пользователя.
- Успешная передача байтов не равна успешной загрузке.
- USB и BOOT-восстановление сохраняются при добавлении новых транспортов.
- Секреты не включать в исходники, ZIP, журналы и чат; подпись не называть шифрованием.
- Перед каждым выпуском: тесты, сборка, обновление generated payload и инструкций, проверка ZIP.

## 9. Как использовать архив

Распакуй `espOS/` и `espos-studio/` рядом. Начни с `espos-studio/SELF_HOSTING.md`. Для USB достаточно установленного Bun и пустого корневого `.env`:

```bash
cd espos-studio
bun install --frozen-lockfile
touch .env
bun run dev
```

Открой `http://localhost:4200` и выбери режим. MicroPython `.bin` скачивается с официального сайта под выбранный модуль; он не включён в этот исходный архив.

Документы: `espOS/docs/WIFI.md` — сеть и риски; `espOS/docs/ROADMAP.md` — общий список направлений; `espos-studio/design.md` — дизайн; `espos-studio/task.md` — история программных проверок. При противоречии старой нумерации roadmap текущий порядок работ задаёт этот план.
