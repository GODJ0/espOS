# espOS Wi-Fi v2 — S3, локальный Studio и Android

Это первый экспериментальный сетевой этап: MicroPython-пакет и интерфейс проверены программно, но реальная ESP32-S3/WLAN ещё не проверена. BLE не реализован. ROM-прошивка, установка MicroPython и восстановление — через USB.

## Возможности

- Проверка общего секрета через подписанные challenge и статус (не постоянное соединение); подписанные запросы, ответы и привязанные ошибки.
- Просмотр каталогов `/apps`, чтение и обновление существующих UTF-8 `.py`, `.json`, `.txt`, `.md` внутри приложения.
- До 16 KiB на файл, до 128 элементов каталога; revision SHA256 предотвращает незаметную потерю чужих изменений.
- Запись через временный соседний файл и rename. Перезапуск — отдельное подтверждаемое действие. Файловая система и поведение rename при отключении питания требуют аппаратного теста; сохраняй резервную копию.
- Нет удаления/создания файлов, обновления `/lib`, `/config.py`, `/main.py`, `/boot.py`, `/network_config.py`, полного Python REPL или firmware OTA.
- Python-файлы приложения выполняются с правами платы при запуске. Это не песочница: не загружай неизвестный код.

## Схема подключения

`браузер ПК / Android / iPhone → локальный espOS Studio на ПК → ESP32-S3 в той же Wi-Fi сети`

Телефону не нужен WebSerial. Компьютер должен оставаться включённым. Публичный Runable-предпросмотр/VPS не видит плату в домашней сети; bridge по умолчанию выключен. Прямой телефон → плата и BLE остаются будущими этапами.

## 1. Первая настройка платы

1. По USB установи обновлённый пакет espOS, содержащий `lib/espos/net_protocol.py` и `net_service.py`.
2. Открой Wi-Fi вкладку Studio. Создай токен (32 случайных байта, 64 hex-символа). Сохрани его приватно вне чата/репозитория; поле пароля позволяет выделить/скопировать значение. Не отправляй токен вместе с журналами.
3. В «Настройка платы через USB» укажи SSID и пароль защищённой доверенной сети. Подтверди замену `/network_config.py` и запиши настройки.
4. Выполни Soft reset через USB. В выводе REPL появится `espOS LAN: IP:8765`. Если не появляется, проверь наличие модулей, пароль, покрытие и ошибки. Открытые Wi-Fi сети этим этапом не поддерживаются.
5. Настрой DHCP reservation для платы в роутере, чтобы IP не менялся.

Отсутствующий `network_config.py` или `ENABLED = False` отключает сервис. BOOT safe mode пропускает сеть. USB Ctrl-C останавливает приложение и отдаёт REPL; сетевой сервер закрывается вместе с основным циклом. Чтобы отключить LAN, по USB установи `ENABLED = False` и перезапусти.

`network_config.py` содержит секреты и исключён из генерируемого пакета Studio. Повторная USB-установка стандартного пакета его не заменяет. Никогда не добавляй этот файл в ZIP/репозиторий.

## 2. Локальный Studio на ПК

Расположи `espOS` и `espos-studio` рядом. В `espos-studio` установи зависимости через `bun install --frozen-lockfile`. В единственном корневом `.env` добавь (IP — примеры, замени своими):

```dotenv
ESPOS_LAN_ENABLED=true
ESPOS_LAN_DEVICE_IP=192.168.1.80
ESPOS_LAN_ORIGINS=http://localhost:4200,http://192.168.1.10:4200
```

- DEVICE_IP — конкретный private IPv4 платы. Не URL, не домен, не IP Studio; порт устройства фиксирован 8765.
- ORIGINS — точные адреса браузера с протоколом и портом, без пути и завершающего `/`.
- Bridge не сканирует сеть, не принимает произвольные адреса от браузера и не следует redirect.
- Запусти `bun run dev` (или build/start по `SELF_HOSTING.md`). Не меняй назначенный порт 4200.
- С ПК открой `http://localhost:4200`. С Android/iPhone в той же сети — `http://IP_ПК:4200`. Введи тот же токен и нажми «Проверить сопряжение / статус». Файлы и reboot разблокируются только после подписанного статуса v2.
- Разреши входящий 4200 только для доверенной LAN в firewall ПК. Если телефон не видит ПК, проверь guest/client isolation, VPN и правила firewall. Не пробрасывай 4200/8765 на интернет.

Для повседневной работы предпочтителен локальный HTTPS (например reverse proxy с доверенным сертификатом); добавь точный HTTPS origin. Обычный HTTP используется только как лабораторный режим доверенной изолированной сети.

## Безопасность и ограничения

Одноразовый nonce действует 15 секунд. HMAC-SHA256 подписывает точные байты JSON; nonce удаляется при проверке, в том числе неуспешной. От master-токена выводятся три разных ключа для challenge, запросов и ответов. Challenge связан со свежим случайным идентификатором клиента; ответ — с nonce, SHA256 точного тела запроса и HTTP-статусом. Bridge проверяет подпись до обработки успеха или ошибки. Ключ не отправляется плате по Wi-Fi. Источник запросов bridge проверяется по точному Origin; это защита от чужого сайта, не полноценная аутентификация компьютера. Владелец токена получает управление приложениями платы.

**HTTP не шифрует трафик.** Если телефон открывает Studio по HTTP, его токен идёт к ПК открытым текстом: перехватчик сможет подписывать команды. HMAC канала ПК → плата проверяет целостность и привязку обмена, но не скрывает файлы и не защищает от DoS, заражённого ПК или похищенного токена. Нет TLS на плате. Не используй в публичной/общей сети; для браузер → Studio предпочтителен локальный HTTPS. Нет обещания универсальной безопасной совместимости с любым телефоном.

Токен/пароль не сохраняются в localStorage. Они находятся в памяти вкладки, в запросе к локальному bridge и на файловой системе платы. «Забыть сессию» очищает UI, но не отзывает токен платы. Переключение вкладки/перезагрузка также сбрасывает UI-сессию. Смена токена, ошибка или reboot очищают доказательство сопряжения; статус проверяется заново вручную.

### Ротация и отзыв — только USB

Создание токена в браузере само по себе не меняет плату. Для ротации создай новый токен, заново введи SSID/пароль, подтверди запись конфигурации по USB и выполни Soft reset. После этого старый токен не должен проходить проверку; проверь старый и новый клиент вручную. Для отзыва подключись по USB, подтверди «Отозвать LAN-доступ по USB»: Studio заменит конфигурацию на `ENABLED = False`, без токена и пароля. Выполни Soft reset и проверь недоступность LAN. При ошибке USB не считай отзыв состоявшимся. Это не обещает физического стирания секрета из flash или резервных копий.

### Формат v2 / несовместимость с v1

Studio и пакет платы обновляются вместе по USB. Неподписанный v1 не поддерживается; автоматического downgrade нет.

- `K_purpose = HMAC-SHA256(master, UTF8("espos-lan-v2/" + purpose))`, purpose: `challenge`, `request`, `response`; результат — 32 сырых байта.
- `GET /espos/v2/challenge?client=<32 lowercase hex>` возвращает `{payload: <строка JSON>, signature: <64 lowercase hex>}`. В payload: protocol `espos-lan-v2`, тот же client, nonce (32 hex), expiresIn `15`. Подпись: HMAC ключом challenge над `UTF8("challenge\n" + payload)`.
- `POST /espos/v2/rpc` передаёт точное UTF-8 JSON-тело и заголовки `X-Espos-Nonce`, `X-Espos-Signature`. Подпись ключом request: `UTF8("request\n" + nonce + "\n") + body`.
- Ответ — такой же envelope. Подпись ключом response: `UTF8("response\n" + nonce + "\n" + SHA256(body).hexdigest() + "\n" + HTTP_status + "\n" + payload)`.
- Ошибки после получения валидного nonce и полного тела также подписаны (включая auth/replay/path/revision). Device busy и ранние ошибки HTTP-парсинга могут быть без подписи: bridge отвергает их как неподтверждённые, а не как достоверный результат команды.
- Не пересериализуй payload перед проверкой. Лимиты: заголовки 2048 байт, тело 24576 байт, ответ bridge 65536 байт; максимум 8 ожидающих nonce, rate limit challenge 250 ms. Автоматических повторов нет.

При timeout или неверной подписи после записи не повторяй её вслепую: результат мог примениться. Проверь плату по USB; после восстановления доверенного обмена перечитай файл и проверь revision/содержимое. Ни bridge, ни UI не повторяют write/reboot автоматически. Обновление файла — не прошивка MicroPython.

## Программная проверка

```bash
cd espOS
python -m unittest discover -s tests -p 'test_net*.py' -v
python -m compileall -q firmware
node tools/gen_payload.mjs
cd ../espos-studio
bun test tests/lan.test.ts
bun run lint
bun run build
```

CPython HTTP-тест использует реальные parser/protocol, но подменяет MicroPython time/asyncio и не тестирует радио. Bun проверяет подмену challenge/ответа, привязку nonce/hash/status, подписанные ошибки, запрет v1 и отсутствие повторов; отдельный тест читает реальные Python-envelope и проверяет Python↔Node совместимость с UTF-8. Дальше нужны реальные тесты S3: ассоциация с сетью, параллельный дисплей/тач, UTF-8 обновление файла, конфликт revision, reboot, потеря питания/сети, USB-ротация/отзыв и Android-браузер.

## Дальше: BLE

Планируется GATT транспорт для того же набора операций и chunked передачи. Ещё нужно реализовать сопряжение, шифрование/авторизацию, лимиты и восстановления. Web Bluetooth подходит не всем браузерам: обычный iOS Safari не имеет native Web Bluetooth. Android — целевая платформа следующего этапа, но поддержка конкретного браузера/телефона будет проверяться отдельно.
