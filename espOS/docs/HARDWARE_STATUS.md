# Аппаратные результаты и точка продолжения

Основание: фотографии, журналы Studio и выводы команд, предоставленные пользователем в текущем тестировании. Это не полная сертификация платы. Исходные фотографии и журналы с сетевыми идентификаторами не включены в публичный исходный архив.

## Подтверждено

- На S3 получены свежий `espOS: ready / headless / USB` и результат `print(2 + 2)` → `4`, в том числе после Reset/переподключения по сообщению пользователя.
- Тестировались две платы: первая через USB-UART `1a86:55d3`, вторая через `0403:6001` (FT232R). Менялись также браузеры; не считать результаты контролируемым сравнением одной платы.
- Ручной BOOT помогал войти в ROM; автоматический вход нестабилен. Стирание/запись и последующий REPL — разные стадии. ROM-ошибка до writeFlash не означает, что flash изменена.
- Обычная S3-сборка на Octal-модуле показала ошибки quad_psram и продолжила работу без внешней RAM. Octal-сборка и свежий headless запуск видны в пользовательском выводе. Полный стресс-тест PSRAM не проведён.
- Последний beginner-журнал содержит успешную запись SPIRAM_OCT и переходы через проверку MicroPython, копирование espOS, проверку свежей загрузки и USB-тест.
- Локальный Studio запущен на Windows. Сетевые настройки записаны по USB. Плата выводит LAN IP и порт 8765, роутер показывает соответствующее устройство подключённым.

## Wi-Fi: текущий блокер

Подписанное сопряжение не прошло. С VPN TCP-тест вернул True через туннельный интерфейс — это не доказательство прямой доступности платы. Без VPN ПК в домашней подсети получает DestinationHostUnreachable; ARP/neighbor для платы содержит нулевой MAC и Unreachable. Аналогичный результат получен для другого Wi-Fi-клиента.

Это указывает на проблему локальной достижимости, не устанавливая конкретную причину. Возможны изоляция клиентов, фильтры ПК/VPN и другие сетевые причины. Роутер видит ПК и плату; доступ к интернету в его списке не равнозначен разрешению обмена между клиентами.

Следующее: проверить изоляцию/гостевую сеть роутера, тест с другого ПК либо отдельно согласованной сети. Ethernet пользователю сейчас недоступен. Не менять токен и не стирать flash для этой проверки. Не отключать firewall целиком.

## Windows: повторный локальный запуск

Открыть PowerShell именно в папке `espos-studio`, содержащей package.json:

```powershell
bun install --frozen-lockfile
if (!(Test-Path .env)) { New-Item -ItemType File -Path .env | Out-Null }
notepad .env
bun run dev
```

В .env включить bridge с реальным private IPv4 платы и точным origin localhost:4200 по WIFI.md. Не создавать .env в System32; файл не должен называться .env.txt. Сервер перезапустить после изменения настроек. Пользовательский .env не входит в архив: сохранить его приватно перед заменой локального проекта.

Если браузер не копирует скрытый токен, можно создать его во втором PowerShell и вставить в приватное хранилище и поле Studio:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
$token = -join ($bytes | ForEach-Object { $_.ToString("x2") })
$token | Set-Clipboard
```

Использовать один и тот же токен при USB-настройке и проверке статуса. Не отправлять секреты в чат. Новый токен в UI сам по себе не меняет плату. После записи перезапустить espOS; Ctrl-C и «Статус REPL» могут остановить приложение вместе с LAN. Не выполнять их во время сетевого теста.

## Дисплей и тач

На фото модуль 2.8 TFT SPI 240x320 V1.2, маркировка XPT2046 читается. Продавец заявляет ILI9341; фактическая работа дисплея ещё не проверена. Питание VCC/LED и подключение требуют проверки; не питать силовую подсветку напрямую от GPIO, проводку менять без USB-питания.

## Доработки

Реализовано в espOS 0.1.1-mvp (только программные проверки, на плате не подтверждено):

- Safe mode без конфликта с ROM: после Reset плата печатает `espOS: hold BOOT now for safe mode (1500 ms)`; BOOT нажимать после отпускания RST.
- Калибровка тача: касание запуска не становится первой точкой, сырые значения без фильтра диапазона, экстраполяция к краям, определение зеркальности и поворота.
- USB-запись: новый raw-REPL handshake на каждую операцию, прерывание при баннере перезагрузки, временный `.espos-tmp`, проверка SHA-256, затем rename.
- Замена файла (USB и Wi-Fi) без удаления оригинала: если rename отказал (например, FAT), Studio/плата не удаляют исходный файл и оставляют проверенную копию `.espos-tmp`. Это fail-closed обработка ошибок, а не гарантия атомарности при отключении питания.
- Windows: генератор payload с корректными путями, `bun run kill:port` через Get-NetTCPConnection/taskkill.

Ещё не реализовано:

- Явный ручной ROM-режим без автоматического сброса.
- Очистка старого Detected в новом диагностическом сеансе; отделение ошибок ROM от после-прошивочного REPL.
- Кнопки показать/копировать токен с обработкой отказа clipboard.
- Более понятная Windows-инструкция и сетевая диагностика в UI.

Wi-Fi файлы/write/reboot, USB-ротация/отзыв, Android, дисплей/тач, safe-mode тайминг, запись на реальную flash и аппаратная SPI-устойчивость остаются непроверенными. Сетевую недоступность платы (`DestinationHostUnreachable`) эти изменения не устраняют.
