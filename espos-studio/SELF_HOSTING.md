# espOS Studio: исходники и свой сервер

## Что находится в архиве

- `espos-studio/`: весь исходный код веб-интерфейса, API, настройки и `bun.lock`.
- `espOS/`: Python-файлы для платы, драйверы и документация.
- Не включены `.env` с секретами, `node_modules`, кеши и локальные базы данных.
- Это исходники, а не готовый установочный бинарник MicroPython. Его нужно скачать с официального сайта под свой модуль.

## Сейчас, без домена

Установи Bun (проект рассчитан на Bun 1.3.14 или совместимый), распакуй архив:

```bash
cd espos-studio
bun install --frozen-lockfile
touch .env
bun run dev
```

Открой `http://localhost:4200`, инструкция находится на `/guide`.
Порт задан в `.runable/ports.json` и читается через `__ports.cjs`; не изменяй его.
WebSerial требует доверенный контекст: localhost или HTTPS. Обычный HTTP по IP сервера не заменяет HTTPS.
USB MVP ориентирован на Chrome/Edge на ПК. Android/OTG и USB на iOS пока не поддерживаются гарантированно. Новый Wi-Fi LAN-интерфейс рассчитан также на Android/iPhone браузер через локальный Studio на ПК; реальные мобильные устройства ещё не проверены.

Текущим маршрутам API (список и загрузка MicroPython) не нужны база данных и секреты Runable.
Пустой `.env` достаточен для USB и каталога MicroPython; Wi-Fi bridge требует явного включения и LAN-параметров.

## Простой старт — USB без дисплея

При открытии Studio выбери «Простой старт» или «Расширенный режим». Выбор ничего не меняет на плате и не сохраняется между перезагрузками страницы. Все прежние инструменты находятся в расширенном режиме.

Мастер рассчитан только на ESP32-S3 DevKitC и Chrome/Edge на ПК. При отключённом питании отсоедини внешние модули, сверь модель, подготовь кабель данных. Выбери USB-порт и запусти проверку ROM: она перезапускает плату, но не пишет и не стирает flash. Другие чипы блокируются. ROM определяет семейство, но не доказывает модель DevKitC и тип памяти.

Если MicroPython уже установлен, попробуй «Проверить установленный MicroPython»: это прерывает приложение, но не стирает flash. Если нужна установка, сверь паспорт/полную маркировку модуля: минимум 4 MiB flash; стандартная сборка для отсутствующей/Quad PSRAM, SPIRAM_OCT — для Octal PSRAM. «Не знаю» блокирует запись. Последняя стабильная полная сборка нужного варианта выбирается автоматически, адрес 0x0 и скорость 115200 фиксированы. Требования: https://micropython.org/download/ESP32_GENERIC_S3/ . Никакой гарантии совместимости по одному названию S3.

Полное стирание требует подтверждения: старые файлы/прошивка/настройки будут потеряны. После записи отдельно проверь ответ MicroPython. Если native USB исчез, выбери новый порт и повтори только проверку чипа/ответа; прошивка не повторяется автоматически.

Установка espOS также требует подтверждения перезаписи. Мастер копирует пакет, меняет DISPLAY_ENABLED и TOUCH_ENABLED на False, заменяет /network_config.py на LAN-disabled конфигурацию без секретов, создаёт маркеры Python-пакетов и проверяет записанный профиль. Он не удаляет посторонние файлы, но перезаписывает пути пакета; сначала сохрани резервную копию. Прежний LAN будет отключён после перезапуска. Физическое стирание старых секретов из flash не гарантируется.

«Перезапустить и проверить espOS» ждёт свежий `MPY: soft reboot`, версию espOS и `espOS: ready / headless / USB`. Просто успешная запись файлов не считается загрузкой. BOOT должен быть отпущен. После потери USB доказательства установки/запуска сбрасываются: новую установку подтверждай вручную. Первый тест считает 2 + 2 через USB, без файлов и GPIO. Экран/тач/Wi-Fi включаются отдельно позже в расширенном режиме.

При ошибке мастер показывает исходную причину, инструкции BOOT/RST и локальный журнал. Он не отменяет запись посередине и не повторяет её сам. Проверены программные тесты и браузерные транспортные mocks; реальная S3/USB/PSRAM ещё требует проверки.

```bash
bun test tests/beginner.test.ts  # отдельно: mock.module подменяет транспорт
python tests/beginner-browser.py  # Playwright/Chrome и запущенный dev server
```

## Wi-Fi LAN / Android — экспериментальный этап

Полная инструкция: `espOS/docs/WIFI.md` в соседнем каталоге. Сначала установи обновлённый espOS по USB, затем во вкладке Wi-Fi запиши SSID/пароль и случайный токен в device-only `/network_config.py`. Soft reset выведет IP платы в USB REPL.

Для локального Studio добавь в единственный корневой `.env`, подставив свои адреса:

```dotenv
ESPOS_LAN_ENABLED=true
ESPOS_LAN_DEVICE_IP=192.168.1.80
ESPOS_LAN_ORIGINS=http://localhost:4200,http://192.168.1.10:4200
```

Перезапусти Studio. На Android/iPhone в той же сети открой `http://IP_ПК:4200`, введи токен и нажми «Проверить сопряжение / статус». Файлы/reboot доступны после подписанного статуса v2. Компьютер остаётся включённым; bridge обращается к фиксированному IP платы на порту 8765. Нет сетевого поиска и произвольного URL-прокси. Dev-сервер слушает интерфейсы ПК; firewall должен разрешать 4200 только доверенной LAN.

Это не универсальный облачный доступ. На публичном VPS/Runable LAN bridge оставляй выключенным. Не пробрасывай 4200/8765 в интернет. HTTP не шифрует содержимое: телефон → Studio передаёт токен открытым текстом, и его перехват даёт доступ. Wi-Fi v2 использует разные производные HMAC-ключи, подписанный fresh-client challenge и ответы/ошибки, связанные с nonce, hash запроса и HTTP-статусом. Это проверка целостности, не шифрование файлов и не защита от DoS/заражённого ПК. Ранние неподписанные ошибки отвергаются как неподтверждённые. Только изолированная доверенная LAN; для локального Studio предпочтителен HTTPS. TLS на плате, BLE и MicroPython OTA ещё не реализованы.

Studio и пакет платы обновляй вместе по USB: старый неподписанный v1 заблокирован, downgrade нет. Создание нового токена не меняет плату: ротация применяется записью SSID/пароля/нового токена по USB и Soft reset. «Отозвать LAN-доступ по USB» с явным подтверждением заменяет конфигурацию на `ENABLED = False` без секретов; после Soft reset проверь недоступность LAN. «Забыть сессию» — только очистка UI, не отзыв. Физическое стирание секрета из flash не гарантируется.

Доступны статус, список/чтение/обновление существующих app-текстов до 16 KiB и подтверждаемый reboot. Core/секретные файлы закрыты. После сбоя write не повторяется автоматически: перечитай файл. Без базы данных и аккаунтов; пароли не сохраняются в localStorage или пакет обновления. Реальная WLAN/Android связь пока не проверена.

## После тестирования: домен и VPS

1. Купи домен и направь его DNS A/AAAA на сервер.
2. Установи Bun и зависимости, загрузи исходники. Не выкладывай исходники и `.env` в публичный каталог веб-сервера.
3. Собери и запусти приложение из корня `espos-studio`:

```bash
bun install --frozen-lockfile
touch .env
bun run build
bun run start
```

`bun run start` использует PM2 из зависимостей и `ecosystem.config.cjs`: Bun обслуживает React-сборку и Hono API вместе на назначенном порту 4200.
Настрой автозапуск PM2 после перезагрузки сервера по инструкции PM2 для своей ОС.

4. Перед приложением поставь reverse proxy (например Caddy) с автоматическим TLS. Пример Caddyfile — замени адрес на собственный домен:

```text
your-domain.example {
    reverse_proxy 127.0.0.1:4200
}
```

5. Открой снаружи только необходимые порты (обычно 80/443 и SSH); 4200 не публикуй напрямую.
6. Проверь `/`, `/guide`, `/api/health`, загрузку списка прошивок и скачивание `.bin`.
7. Подключение платы тестируй в браузере на своём компьютере. USB не передаётся на VPS: код в браузере обращается к локальной плате.

Одного каталога `dist` для полной функциональности недостаточно: сервер нужен для списка прошивок и прокси скачивания с micropython.org.
Список и скачивание зависят от доступности micropython.org. Шрифты загружаются с Google Fonts; при необходимости их можно разместить локально.
В приложении сохранена аналитика шаблона Runable — учти её при подготовке политики конфиденциальности публичного сайта.

## Обновление файлов для устройства

Сохраняй соседнее расположение каталогов `espOS` и `espos-studio`:

```bash
cd espOS
node tools/gen_payload.mjs
cd ../espos-studio
bun run build
bun run start
```

Скрипт обновляет `espos-files.ts`, который использует кнопка установки espOS.

## До публичного релиза

### Web Flasher: семейства и ограничения

- Есть ручной выбор и определение семейства через ROM: ESP32, ESP32-S2, ESP32-S3, ESP32-C2, ESP32-C3, ESP32-C6.
- Кнопка «Определить чип» перезапускает плату, но не стирает flash, не пишет прошивку и не загружает RAM-stub. USB VID/PID не считается идентификатором чипа.
- Полные официальные образы записываются с `0x1000` для ESP32/S2 и `0x0` для S3/C2/C3/C6. Подключение и запись идут на 115200 baud.
- Перед ROM-подключением проверяются базовый ESP-заголовок и ID семейства образа. Перед стиранием/записью проверяется совпадение подключённого чипа с выбранным профилем.
- Свой `.bin` должен быть полным bootloader-first образом для указанного адреса. Нужен явный чекбокс подтверждения; app-only/app-bin, UF2 и ZIP не поддерживаются. Полная сборка с OTA-разметкой допустима. Заголовок не доказывает полноту образа: разделы, подписи, flash/PSRAM и кварц автоматически не проверяются.
- ESP32-C2 generic требует минимум 4 MiB flash и кварц 26 MHz. Вариант flash/PSRAM для остальных семейств также выбирается по модулю и официальной странице MicroPython.
- При исчезновении native USB после сброса нужно подключиться заново. Автоматического повторного стирания или прошивки нет. Для диагностики доступна кнопка «Скачать журнал».
- «Статус REPL» — отдельное действие, прерывающее приложение. Автоматического опроса REPL во время подключения нет.
- Многосемейный Web Flasher не означает перенос espOS: установка, HAL и схема подключения пока рассчитаны на ESP32-S3 DevKitC.

### Диагностика и восстановление

В панели «Запись» доступен блок диагностики даже без подключённой платы. Он показывает исходную ошибку, вероятную категорию, последний этап и инструкцию BOOT/RST. Категория — подсказка, не аппаратный диагноз.

«Выбрать USB-порт заново» закрывает старый порт и вызывает выбор нового: без ROM-команд, стирания, записи или REPL-опроса. Физическое отключение USB и ошибка потока снимают статус «подключено». Автоматического повторного flash нет; кнопки восстановления блокируются во время операции. При сбое внутри `writeFlash` явно показывается, что flash мог быть стёрт или записан частично. Успех `writeFlash` не означает успешную загрузку MicroPython.

Журнал — локальный TXT с UTC-временем, этапами, исходной ошибкой, образом, целевым/обнаруженным семейством, адресом, eraseAll, baud, USB VID/PID и user-agent. Параметры фиксируются на момент запуска: смена профиля после сбоя не переписывает предыдущую сессию. Хранится последняя сессия в памяти панели (до 64 000 символов событий); выход с вкладки/перезагрузка страницы её сбрасывает. REPL не включается автоматически. Проверь файл перед отправкой: сообщения esptool могут содержать идентификаторы устройства.

Проверка разработки:

```bash
bun test tests/flasher.test.ts tests/diagnostics.test.ts
# Отдельный процесс: предыдущие тесты подменяют serial через mock.module.
bun test tests/serial.test.ts
python tests/recovery-browser.py  # нужны Python Playwright, Chrome и запущенный dev server
bun run lint
bun run build
```

Сценарии основаны на официальной инструкции Espressif: https://docs.espressif.com/projects/esptool/en/latest/esp32/troubleshooting.html. Не меняй eFuse/Secure Boot/шифрование для обхода ошибки.

Проверены программные тесты защиты, выдача API и заголовки официальных образов шести семейств, а также браузерный интерфейс. Реальная ROM-связь, стирание, запись и загрузка на платах ещё не проверены.

Прошивка ещё не проверена на реальной плате. Проверить flash/PSRAM-вариант, питание TFT, подсветку, контроллер тача, калибровку и восстановление после ошибки.
Встроенный SVG — логическая схема подключения, не физическая разводка разъёмов и не подтверждение совместимости любого ILI9341-модуля.
Не питать силовую подсветку напрямую от GPIO. `TFT_BL = None` — безопасное значение по умолчанию.

Перед публичным хостингом также провести security-review: ограничить частоту и объём запросов к прокси прошивок,
проверить обработку путей статических файлов и политики внешних запросов. Этот архив — рабочая версия для разработки, не аудированный production-релиз.

## Реклама

Кампании не созданы и не запущены. Бюджет — 0 до завершения и аппаратных тестов.
Будущий основной результат: скачивание прошивки; первая аудитория — русскоязычные разработчики ESP32/MicroPython в России и выбранных странах СНГ.
Платформы, доступность размещения, стоимость и географию стоит проверить заново непосредственно перед запуском.
